## 二、打包（独立 exe）——PyInstaller

> 目标：把 demo/演出打成免 Python 环境的单文件 exe（Windows），用于分发试玩。
> 实测环境：`~/.workbuddy/binaries/python/envs/default`（pyglet 2.1.16）。

### 标准命令（以隧道 demo 为例）

```bat
python -m PyInstaller --onefile --console --name tunnel_demo ^
    --paths . --distpath dist --workpath build/pyi --specpath build/pyi ^
    examples/demoscene_tunnel.py
```

- `--paths .`：让 PyInstaller 能把项目根加入分析路径（`examples/_harness.py`
  会 `sys.path.insert(PROJECT_ROOT)`，但那是**运行时**逻辑，打包器需要静态可见）；
- `--console`：保留控制台（便于看 `--smoke` 输出与日志；正式分发可换 `--windowed`）；
- 产物：`dist/tunnel_demo.exe`（`dist/`、`build/` 已 gitignore）。

### 实测结果（2026-10-08，隧道 demo 首验）

| 项 | 值 |
|----|----|
| 工具 | PyInstaller 6.22.3（隔离 venv，pyglet 2.1.16） |
| 产物 | `dist/tunnel_demo.exe` —— **10.8 MB**（单文件） |
| 构建 | ~20 秒（依赖安装另计）；**无需任何 hidden-import 调整** |
| 运行验证 | `dist\tunnel_demo.exe --smoke 3` → `[smoke] auto-close in 3.0s` + `EXIT_OK`，**正常退出（RC=0）** ✅ |
| 结论 | 「pyglet + `_harness` + 项目内导入」的单文件打包链路**已打通**。引擎系 demo（engine_showcase / 大演出）依赖面更大，首次打包若报 ModuleNotFound，用 `--hidden-import` 逐个补齐即可 |

### 引擎系 demo 验证（2026-10-09）

| exe | 大小 | 运行验证 |
|-----|------|----------|
| `engine_showcase_demo.exe` | 10.9 MB | `--smoke 3` → `EXIT_OK`，RC=0 ✅ |
| `material_lab_demo.exe` | 10.9 MB | `--smoke 3` → `EXIT_OK`，RC=0 ✅ |

**结论**：`engine/` 包（PBR/后处理/场景/物理/拾取全链路）被 PyInstaller
自动追踪打包，**无需任何 hidden-import**——`--paths .` 即可。

**打包后路径机制（实测三例）**：冻结模式下 `PROJECT_ROOT` / 截图落点
**因 demo 的写法而异**（入口脚本自算的 `ROOT` 与 `_harness.PROJECT_ROOT`
在打包后解析各不相同）：engine_showcase → 运行目录 `docs/`；
minecraft → `%TEMP%\docs\`（系统临时目录）。共同点：**都能写出、不崩**
（跨机器可用），差异只在落点。

- 对发行版的影响：自动抓帧的截图可能落在「运行目录/`docs/`」或「`%TEMP%\docs\`」
  ——无害、可随时删除；
- 已加固：抓帧失败（只读目录等）**只告警不打断演示**（`_harness._capture_due`）；
- 后续改进项：「冻结模式跳过自动抓帧」（消除发行版中的截图副产物）。

### 已知注意点

1. 依赖「项目相对路径」的功能（读 `assets/`、`--shot` 输出）在 exe 里落点

3. 多 demo 可共享分析（`--onedir` 减体积），或按需单文件。

## 三、发布路径（建议）

### 3.0 铁律：**发行版重建必须攒批**（2026-10-13 定，全哥要求）

Gitee 的 release **附件只能追加、不能单独替换/删除**（API 的 assets 只给 `name` +
`browser_download_url`，没有 `id`）。因此：

- 想替换/改名**任何一个已有附件**（哪怕只换一条 mp4）⇒ 只能 `DELETE /releases/{id}`
  **删掉整个 release** → `POST /releases` 重建 → **重传 362MB 全部附件**；
- 所以**不要每改一处就问"要不要重建"**，而是：

> **凡是影响成片/附件的改动（demo 视觉调整、渲染特性、引擎化改造…），一律登记到
> 「待重建清单」，攒到发布节点一次性重建。**

**重建前必须做的一件事（P5-c 新踩、直接写进流程）**：删 release 会**连附件一起清掉**，
而有些附件**本地已经没有了** —— 本项目的 `dist/` 被 gitignore，`3dworld-demo-pack-20261009.zip`
（63.9MB）当时只存在于 Gitee。所以重建的**第一步**是：

```bash
# ① 匿名把"不可再生的附件"取回本地（顺便验证匿名可下载）
curl -sL -o dist/3dworld-demo-pack-<日期>.zip \
  https://gitee.com/siwpan/3dworld/releases/download/<tag>/3dworld-demo-pack-<日期>.zip
# ② 校验它是完整可用的（不是半截 HTML 错误页）
python -c "import zipfile,hashlib; p='dist/...zip'; print(hashlib.sha256(open(p,'rb').read()).hexdigest(), zipfile.is_zipfile(p), len(zipfile.ZipFile(p).namelist()))"
```

实测：66,966,891 字节 / sha256 `51930d79…` / 7 个条目（6 exe + README.txt）✅ ——
**没有这一步，重建就等于永久丢失 exe 包**（重打包要装 PyInstaller，本机 venv 里没有）。
