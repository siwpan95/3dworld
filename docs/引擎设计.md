# 3dworld 核心引擎（engine/）设计与技术要点

> 2026-10 从 core/ logic/ presentation/ 中抽取的零业务依赖渲染引擎。
> 本文记录架构决策、联网调研结论与实测踩坑，供后续维护与扩展参考。

## 一、模块地图

```
engine/
├── mathkit.py    纯数学：矩阵(列主序)/四元数/插值/Hammersley/半球核   [无 GL，可单测]
├── timeline.py   时间轴：Sampler(LINEAR/STEP/CUBICSPLINE)/Channel/Timeline/播放机 [无 GL]
├── frustum.py    AABB/包围球/视锥(Gribb-Hartmann)/空间哈希            [无 GL]
├── geometry.py   MeshData + 程序化几何(box/sphere/torus/cylinder/...)  [无 GL]
├── gltf.py       glTF 2.0 / GLB 解析（sparse、动画、PBR 材质）         [无 GL]
├── picking.py    射线：屏幕反投影 / ray-AABB/球/三角形(Möller-Trumbore) [无 GL]
├── physics.py    AABB 碰撞 + 重力 + 分轴解算（move-and-slide）          [无 GL]
├── serialize.py  场景 JSON 序列化 + 热重载 watcher                     [无 GL]
├── material.py   PBR 金属-粗糙度材质（对齐 glTF）                      [GL]
├── shaders.py    全部 GLSL（330 core）：PBR/天空/IBL 烘焙/后处理        [GL]
├── targets.py    RenderTarget(MRT)/MipTarget(逐 mip 可渲染)            [GL]
├── mesh.py       Mesh / InstancedMesh（GPU 上传 + 实例缓冲管理）        [GL]
├── env.py        光照环境：程序化天空 + IBL 三件套烘焙                  [GL]
├── postfx.py     SSAO + Bloom 金字塔 + 合成（ACES/gamma/暗角）          [GL]
├── renderer.py   MRT 几何 pass + 后处理编排 + 透明排序                  [GL]
├── camera.py     Camera / OrbitCamera / FlyCamera                      [无 GL]
├── scene.py      Node 场景图（TRS、脏标记、剔除收集）                   [无 GL]
├── perf.py       帧统计(p1/jank) + GPU 计时查询 + 渲染计数              [GL 可选]
├── hud.py        屏幕空间 HUD                                          [GL]
└── app.py        EngineApp：窗口/CLI/HUD/截图/基准/性能面板             [GL]
```

依赖方向：`app → renderer → postfx/mesh/scene → 纯数学层`，反向禁止。
`logic/animation.py`、`logic/camera.py`、`logic/playback.py` 已改为 engine
的兼容再导出层（12 个既有测试保持全绿）。

## 二、渲染管线

```
天空 pass ─┐
           ├─ MRT: COLOR0=HDR 颜色(RGBA16F)  COLOR1=视空间法线+线性深度
几何 pass ─┘        │
                    ├─→ SSAO(半分辨率,24 样本半球核) → 4x4 盒式模糊
                    ├─→ Bloom: 软膝盖阈值+Karis → 13tap 降采样链 → tent 上采样累加
                    └─→ 合成: HDR*AO + Bloom → 曝光 → ACES → 暗角 → gamma → 屏幕
```

### 关键决策

| 决策 | 选择 | 放弃的方案与原因 |
|------|------|------------------|
| 环境贴图 | 等距柱状 equirect | 立方体贴图：pyglet 无 CubeMap 类，自造成本高；equirect 极点畸变对低频天空不可见 |
| 预过滤镜面 IBL | 逐 mip 级 GGX 重要性采样 | 单张大模糊核：贵且有方块感；mip 链配合 `textureLod(roughness*maxLod)` 是 LearnOpenGL/COD 的标准做法 |
| G-buffer | MRT 两张（颜色+法线/深度） | 全延迟：工程量大；视空间法线+线性深度已够 SSAO 用，省一个附件 |
| AO 半分辨率 | 是 | AO 是低频信号，全分辨率纯烧 GPU |
| IBL 漫反射 | 烘焙时存 E/PI | 着色器端 `diffuse = albedo * tex`，不用每帧除 PI |

## 三、实测踩坑（全部在真机 Intel UHD / GL 4.6 复现并修掉）

1. **mip 链不完整 → 采样全黑**
   只分配 6 级 mip 而不设 `GL_TEXTURE_MAX_LEVEL` 时，纹理 mipmap-incomplete，
   `LINEAR_MIPMAP_LINEAR` 采样静默返回黑（`glCheckFramebufferStatus` 看不出来）。
   症状：金属材质（只有镜面 IBL）全黑，介电体正常。

2. **pyglet 建纹理会冲掉当前纹理绑定**
   `ImageData.get_texture()` 把新纹理绑到"当前激活的纹理单元"。渲染中途懒创建
   默认贴图（白/法线/黑）会把 BRDF LUT 从 2 号单元上挤掉。修复：创建时保存并
   恢复 `GL_ACTIVE_TEXTURE` 与 `GL_TEXTURE_BINDING_2D`（`targets.make_solid_texture`）。

3. **pyglet 实例属性必须出现在初始 data 里**
   `vertex_list_instanced` 只在遍历 data 时给属性打 `instance` 标记；漏传的
   后果是实例缓冲永不扩容、divisor 不设置——只画第 0 个实例且**完全不报错**。

4. **MRT 必须显式 `glDrawBuffers`**
   attach 完不调它，COLOR1 不写入；且必须在 bind 之后调。

5. **pyglet `Framebuffer.clear()` 在 MRT 下抛 GL_INVALID_VALUE**
   它把 `COLOR_ATTACHMENTi` 的枚举值 OR 起来喂给 `glClear`（要的是
   `GL_COLOR_BUFFER_BIT`）。自己写 glClear。

6. **`attach_texture_layer` 对 2D 纹理直接 INVALID_OPERATION**
   它走 `glFramebufferTextureLayer`（3D/数组纹理专用）。渲染到 mip 级要用
   `glFramebufferTexture2D(..., level)`。

7. **pyglet 默认 `debug_gl=True`，每次 GL 调用都做 glGetError 往返**
   cProfile 实测占每帧 Python 耗时 ~44%（4 秒 27 万次 errcheck）。
   `engine/app.py` 已关（`pyglet.options['debug_gl'] = False`），基准从
   28.7 fps → 114.7 fps。排查渲染问题时在入口改回 True。

8. **未使用的 uniform 会被驱动优化掉**
   之后 `program['name'] = ...` 直接抛 ShaderException。实例化顶点着色器
   必须真的用上 `normal_mat`，否则赋值报"Uniform not found"。

9. **GLSL 3.30 的 sampler 数组不允许动态下标**
   点光源写成 4 个具名 uniform；SSAO 采样核在着色器内用 radical-inverse 现算。

10. **物理分轴解算的两条铁律**
    - 候选查询的包围盒外扩**不能原地** `expand`（会把碰撞盒撑大，物体悬空半格）；
    - 解算某轴时另外两轴必须**严格重叠**（接触不算），否则"站在地上"会被地面
      当成墙沿水平方向弹飞。

## 四、程序化音频（engine/audio.py + logic/kkrieger_audio.py）

kkrieger 的配乐与音效同为程序生成：乐谱规则进代码，首次运行离线渲染成
WAV 缓存（`assets/kkrieger_ost.wav`，120s / 32kHz / 16-bit mono / 7.3MB），
之后由 `TimelineAudio`（pyglet.media.Player 封装）与时间轴同步播放。

- **合成器**（纯 Python，无 numpy）：`Track.tone/noise/sweep`（振荡器 +
  ADSR + 一阶低通）→ 加法混音 → 归一化 0.92 → `wave` 标准库写盘。
  120s 约 1.8 万个音符事件、两千万次采样运算，首帧渲染约 10~25s（一次性）。
- **音画对齐是"编译期"的**：配乐作曲层直接 import 动画层的时间常量
  （幕边界 / 开门时刻 / 核心脉冲周期 6s / 灯带熄灭节奏），SFX 按**采样级
  精度**烘进同一条轨道——不用做多轨对时。
- **播放同步**：`Player.loop=True`（源时长=时间轴时长，循环无缝）+ 每帧
  漂移校正（|player.time - playhead| > 0.25s 才 seek，频繁 seek 会爆音）；
  seek 类按键显式双跳（时间轴 + 音频）。
- **驱动**：pyglet 2.x Windows 默认 (xaudio2, directsound, openal, pulse,
  silent)，本机实测 XAudio2；无声卡自动落 silent 驱动，播放调用安全无效化。
- **录制带声**：`scripts/record_all.py` 录完视频后若存在 OST，会自动用
  ffmpeg 把配乐混进 MP4（`-c:v copy -c:a aac -shortest`）。
- **实测结构**（RMS 分段）：铺垫 0.035 → 顶点 0.235 → 撤离留白 0.000 →
  突入 0.196 → **爆发 0.437** → 余音 0.022（循环首尾静音对齐）。

## 五、性能（1280x720，vsync off，Intel UHD 核显）

| 配置 | mean | median | p1 | jank>20ms |
|------|------|--------|----|-----------|
| 优化前（debug_gl 开 + 逐实例材质） | 28.7 | 35.1 | 2.6 | 100% |
| 关 debug_gl + 材质去重 + 矩阵去重 | **114.7** | **139.7** | **94.3** | **0.4%** |

三个优化点（按收益排序）：
1. 关 `debug_gl`（~4 倍）；
2. 材质按"同材质相邻只应用一次"去重 + 模型矩阵与上次上传值比较跳过；
3. 动态实例场走 `write_raw`（每属性一次上传），不逐实例 set_region。
