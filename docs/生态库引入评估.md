# 生态库引入评估：bloodmusic / allin-engine

> 2026-10-09 · 评估对象：siwpan 自研、已在 PyPI 发布的两个库（均 MIT）。
> 方法：本地源码实证（隔离 venv），对照 3dworld 现状逐点评估接入价值。

## 一、结论速览

| 库 | 与 3dworld 关系 | 建议 | 推荐接入方式 |
|----|----------------|------|--------------|
| **bloodmusic**（程序化音频合成引擎） | **强相关**——3dworld 自带「程序化配乐」基因（kkrieger / nordic 的 OST 均为自研合成器离线生成） | **建议引入** | **离线配乐工具链**（生成期依赖，不进运行时）：以其合成/乐理/效果链升级 OST 生成；交互化方向可用其 interactive 自适应音乐与 SFX |
| **allin-engine**（统一游戏引擎） | **异构**——面向 2D / 卡牌 / TRPG / 终端场景，与 3d 渲染栈不同路 | **按需引入局部模块**（不整店引入） | ① `ai/decision` 行为树/状态机（零依赖）→ 交互化 NPC / 演出导演；② 固定步长循环思路 → 物理步长改造；③ `utils/font`（CJK + PyInstaller 兼容）→ HUD 与打包字体；④ `media/formula_engine` → 场景 JSON 参数表达式 |

## 二、实证记录（2026-10-09，隔离 venv）

### bloodmusic（本地 `<PATH>` → 包 `bloodmusic` 2.0.0）

- 安装：editable + numpy / scipy / sounddevice / soundfile / pydub / **audioop-lts**
- ✅ **AutoWav 零依赖创作**：11.7s 音乐（旋律 → 低音 → 混音 → 混响全链路）
- ✅ **风格编配单曲**（`album_maker style electronic`）：编配完整（BPM / 调 / 和声 / 乐器 / 节奏五轨 stems）→ `song_final.wav`
- ✅ **电影感单曲**（`style cinematic --bars 64`）：**48 秒**「深海 · 宏大/史诗」（80 BPM / Em），
  一次渲染成功（渲染耗时仅约 30 秒）
- 实证产物（工作区 `bloodmusic_样例/`）：`autowav_即兴创作.wav`（11.7s）·
  `electronic单曲_16bars.wav` · `cinematic单曲_48s.wav`
- 依赖坑（记账）：Python 3.13 下需补 **`audioop-lts`**（`audioop` 已从标准库移除，pydub 混音链路依赖）；**`sounddevice`** 必须装（包 `__init__` 顶层 import `playback`，否则连 `autowav` 都起不来）

### allin-engine（本地 `<PATH>` → 包 `allin_engine` 1.0.0）

- ✅ 零依赖核心**零障碍直跑**（PYTHONPATH 即可）：
  - `example_quickstart.py`：6 例全过（ECS / 战斗 / 一键装配）
  - `example_decision_ai.py`：7 例全过（**行为树 tick / 差分引擎 / ECS 脑 / 固定步长主循环**）

## 三、接入点详评（对照 3dworld）

### A. bloodmusic → 配乐管线（建议优先）

对齐现状：3dworld 的 OST 生成 = 「离线合成 → WAV 缓存 → 音画同源时间对齐」，
与 bloodmusic 的能力面板天然重合：

1. **保留** 3dworld 的时间轴对齐机制（音画同源由时间常量驱动；bloodmusic 负责「声音内容」）；
2. **替换/增强** `logic/kkrieger_audio.py` / `logic/nordic_audio.py` 内部的合成段
   （振荡器/包络/音效 → 用其合成器与效果链；乐理由其音阶/进行/马尔可夫生成）；
3. **收益**：音色库（FM / Karplus-Strong / Granular）、专业效果链（混响/压缩/延迟）、
   SFX 预设（交互化时直接用）、interactive 自适应音乐（未来交互 demo 的配乐方案）；
4. **成本**：生成期依赖 numpy/scipy（数十 MB）——**运行时仍仅 pyglet，零新增依赖**；
5. 试算口径：见工作区 `bloodmusic_样例/`（3 个 WAV 实证）。

### B. allin-engine → 局部模块

| 模块 | 用于 3dworld 什么 | 判断 |
|------|-------------------|------|
| `ai/decision`（行为树 / HSM / 决策树，零依赖） | 交互化方向的 NPC 与「演出导演」逻辑 | ✅ 值得（与现有事件总线可共存） |
| `core/game_loop.FixedTimestepLoop` | 物理/动画的固定步长稳健性（防死亡螺旋） | ✅ 借鉴思路（小改造，无需引入包） |
| `utils/font`（本地 CJK 字体 + 系统兜底 + PyInstaller 兼容） | HUD 字体与**打包后字体兜底**（呼应 S3） | ✅ 值得参考实现 |
| `media/formula_engine`（安全公式求值） | 场景 JSON 参数表达式（LLM 场景增强） | ○ 可选 |
| ECS / 战斗 / TRPG / world | —— | ✗ 不适用（3dworld 非此形态） |

### C. 状态机 / 决策能力的源头：zhuangtaiji（补充勘察，2026-10-09）

`allin_engine.ai.decision` 只是**子集入口**（并入 4 范式）；其完整源头是
**zhuangtaiji（多范式决策引擎 · 可视化工作台；本地 `<PATH>`，
纯标准库零依赖）**——3dworld 的演出 / 交互化可深挖的能力远超 allin 子集：

| zhuangtaiji 能力 | 对 3dworld 的价值 |
|------------------|-------------------|
| 9 范式（FSM/HSM/行为树/决策树/差分 之外，另有 **Petri 网 / 马尔可夫链 / 规则引擎 / 决策表 / LLM Agent**） | 马尔可夫 → **演出随机变体**；规则引擎（when 条件→动作）→ **声明式编排**；Petri 网 → 多资源并发约束 |
| **编排层**：事件总线（`*` 通配订阅）+ 声明式绑定（`when 事件 → then 动作`） | 「到点/到条件做什么」的高层表达——比手写窗口函数高一级，与 3dworld 事件总线可分层共存 |
| React + react-flow 编排编辑器（拖拽建节点 / 连线建绑定 / 单步驱动 / 运行轨迹） | 未来「可视化导演台」的直接参考 |
| `core/kernel/`（Context/effect/inject）+《Cordis 内核重构方案》 | 与 3dworld 的 Cordis 试点同向，可互相参考 |
| `tools/run_tests.py` 门禁 + `kernel_demo.py`（七个真实痛点） | 工程化与内核设计的参考样例 |

**取用建议**：轻量场景用 allin 的 `ai/decision`（已实测）；**进阶编排 / 随机化 /
声明式规则**参考或按需提取 zhuangtaiji 模块（零依赖、可 PYTHONPATH 直引；
记账：MIT，siwpan 自研）。

## 四、建议与下一步

1. **bloodmusic**：开一个 `experiments/bloodmusic_ost/` 试点（**2026-10-13 已退役**：原生 OST 已在 `logic/kkrieger_audio.py`（含第六幕），见 CHANGELOG 的试点去向表）——把 kkrieger 的一个乐章用
   bloodmusic 重制做 A/B 对照；通过后再定「替换 vs 增强」口径（保持运行时零依赖不变）。
2. **allin-engine**：按局部模块取用（decision / 字体 / 步长），**不引入整包依赖**；
   若未来交互化需要，可从 `ai/decision` 起步。
3. 记账：两库均为 siwpan 自研（MIT），来源与许可明确，无第三方合规风险。
