3dworld · 架构与设计文档

分析对象：D:\projects\repos\3dworld（导入包 world3d，发行名 3dworld，v0.6.0）。 纯 Python + pyglet 2.x / OpenGL 的「程序化优先、确定性、可 headless 验证」3D 场景·动画引擎（零外部素材）。

0. 项目速览

定位引擎库（演示程序 39 个已剥离至独立仓 siwpan/3dworld-demos）
导入/发行名import world3d / pip 包 3dworld（Python 包名不能以数字开头）
技术栈Python ≥3.11 · pyglet 2.1.16 · OpenGL (GLSL 330 core) · vendored Cordis v4.0.0
运行时依赖pyglet、PyYAML≥6,<7、watchdog≥4,<7（Cordis 硬依赖）
规模world3d/ 下 162 个 .py；9 个玩法内核；15 个共同核服务；10 棵配置树
治理机械门禁 verify.py(15 条) + check_imports.py；pre-commit + GitHub Actions CI（win + ubuntu EGL）

一句话架构：用 Cordis 服务图把「配置树 (configs/*.yml)」所描述的共同核 + 玩法内核声明式挂载；内核通过 ctx.<service> 消费 15 个共同核（渲染/地形/实体/经济/规则/音频/时间轴/粒子/SDF…），引擎层 (engine/) 提供零业务依赖的可复用渲染与场景能力，逻辑层 (logic/) 提供纯函数、可 headless 单测的程序化生成与行为算法。

1. 系统分层架构

依赖铁律：只允许向下 games → core → engine → pyglet/GL；presentation → logic → core，反向禁止；内核之间、游戏之间不得横向 import（共享件一律上提）。

1.1 宿主 / CLI 层（host · cli）

  • host/tree.py — 配置树挂载统一入口：load_tree(Cordis Loader + drain 子插件)、await_ready(等 want 服务可达且 render.live_count()>0)、mount_tree(一键 Context→挂树→等就绪)。demo 与 headless 验证走同一条挂载路径。
  • host/registry.py — SERVICES 短名表（24 项：13 共同核 + 11 内核服务，fps/maze、puzzle/grid 同模块双服务）。封闭白名单；bind(name) 为每个短名合成 _3dwsrv.<name> 宿主模块。
  • host/pipeline.py — 场景校验流水线（Cordis fiber 可逆副作用）：SceneCheckService → LoaderService(inject scene_check) → ReporterService(inject scene)。
  • cli/config_boot.py — 9 内核 + 13 共同核 headless 验收；cli/frame_plan.py — 帧图门禁（16 种效果组合）。
  • Cordis v4.0.0（vendored vendor/cordis/src）：Context / Loader / Service / inject 依赖图自动排序 / ctx.effect 可逆副作用。

安全点：.yml 的 name 会被 Cordis importlib.import_module 直接导入（≈执行代码）。_validate_entry_names 强制白名单（_3dwsrv. / core. / games. 前缀），把「评审绕过」钉死。

1.2 玩法内核层（games/<name>/kernel.py）

9 个 Cordis 内核，是业务编排所在：void(星阑) · tower_defense(戍卫之路) · godhand(神之手) · fps(迷堡枪影,+maze) · puzzle(归仓,+grid) · storm(弹潮) · hall(静馆) · pulse(落音) · brickward(砖境, BQM 机制致敬)。每个内核只声明 inject = ['render','rules','economy','entity', …]，由 Cordis 按依赖图自动排序挂载，内核之间零耦合。

1.3 共同核 / 子系统层（core/*_core.py + contracts.py）

15 个共享服务（CORES 表）：render · terrain · entity · input · hud · pathing · economy · audio · timeline · particles · rules · sdf · inventory · skills · loot。

  • core/contracts.py — 15 个 @runtime_checkable Protocol 契约 = 插件 ABI（单一事实来源）。只 import typing，无 Cordis / 无 GL 也能 import；verify() 核对每个契约声明的「现有模块」真能 import。
  • core/render_core.py — 渲染共同核 RenderService：只提供 GL 资源原语（compile_program / upload_mesh / release）与绘制入口，不持有游戏状态；headless 下仅做句柄记账与回滚语义，live_count() 供 await_ready 判定就绪。
  • 其余核：地形高度场编辑、实体注册表、A*+编队寻路、KV 经济、程序化音频、时间轴/关键帧、GPU 粒子数值步进、SDF/体素、背包/技能/掉落、波次/胜负规则。

1.4 引擎层（engine/*）

  • 渲染管线：renderer(MRT 几何 pass) · scene(Node 场景图) · mesh · material(PBR 金属-粗糙度) · shaders(GLSL 330) · targets(MRT/Mip) · postfx(SSAO + Bloom + 合成：曝光/ACES/暗角/gamma)。
  • 进阶渲染：csm · volumetrics · dof · motionblur · oit(WBOIT) · pointcloud(EDL) · gpu_cull(compute 剔除+LOD+命令生成) · compute · framegraph · terrain_lod(CDLOD) · terrain_clipmap。
  • 资产/场景：gltf · asset/gltf_lite · geometry · proctex · serialize(JSON 热重载)。
  • 交互/物理：camera · frustum · picking · physics · rid。
  • 时间/动画：timeline · animation · skeleton · skin · ozz_lite · shot。
  • 音频/工具/平台：audio · adaptive_music · mathkit · perf · fsm · orchestration · reflect · hud · fonts。
  • 平台/表现：platform/app.py(DemoApp) · presentation/*(WorldApp 48s 演出 / KKApp 150s 漫游 / world_renderer)。
  • 导入器：importers/source2(VPK / KV3 v5 / LZ4 / meshopt / vmdl→MeshData)。

engine/__init__.py 用 _safe 延迟导入保证「无 GL 上下文也能 import engine」；公共面由 __all__ 收口，world3d/__init__.py 再转发。

1.5 逻辑层（logic/*）

纯函数 / 无 GL / 可 headless 单测，被 presentation 消费（依赖方向 presentation → logic → core）。

  • 程序化生成：terrain · voxel · waves · blocks · wfc · ca · lsystem · noise · curves · dungeon · town
  • 行为/AI：boids · behavior_tree · physics3d · fov
  • 演出/音频：choreography · kkrieger · fusion_audio · kkrieger_audio · nordic_* · liminall_* · kid_a · sandward
  • 兼容再导出层：animation / camera / playback 已改为 engine 同名件的转发层（旧测试全绿）。

2. 核心模块关系（谁消费谁）

configs/cordis.<name>.yml
        │ (name 短名 → host.registry.bind → _3dwsrv.<name> 宿主模块)
        ▼
host.tree.load_tree ──▶ Cordis Loader (inject 依赖图自动排序)
        │
        ▼
games/<name>/kernel.py  (Service, inject=[render, rules, economy, entity, ...])
        │  消费 ↓ 通过 ctx.<service>
        ├──────────────▶ core/*_core.py   (15 共同核；render_core 管 GL 资源原语)
        │                        │ 调用 ↓
        │                        ▼
        │                  engine/*  (renderer/scene/mesh/shaders/postfx/...)
        │                        │ 依赖 ↓
        │                        ▼
        │                  pyglet / OpenGL
        └──────────────▶ logic/*  (纯函数：程序化生成 / 行为 / 演出，经 presentation 接入)
  • 内核不直接碰 GL——所有 GPU 资源经 ctx.render（RenderService）的 compile_program/upload_mesh/release 原语创建与回收，句柄记入 live_count()。
  • 内核不改变引擎——engine/ 是通用件；同一份 Renderer / Scene 被 9 个内核共用。
  • 确定性：void 内核价格/事件冲击由 (seed, station, good) 派生相位，同种子同世界，录制与验收可锁定（test_noise 还做 golden 交叉验证）。

3. 核心数据流

3.1 配置驱动挂载（启动，boot）

  1. configs/cordis.<name>.yml 声明「本次挂哪些服务 + 各自 config」。
  2. host.tree.load_tree：yaml.safe_load → _resolve_service_names(短名经 registry.bind 换成 _3dwsrv.<name>) → _validate_entry_names(白名单) → loader.root.update(data)。
  3. Cordis Loader 按 inject 依赖图自动排序构造各 Service。
  4. 每个 Service.__cordis_init__ 取 GL 句柄 / 生成实体 / 用 ctx.effect(...) 登记可逆副作用。
  5. await_ready(want) 等 want 中服务全部可达且 render.live_count()>0，返回 ctx。

「demo 怎么挂的 = 验证怎么挂的」：examples 与 cli/config_boot 共用 mount_tree 与同一组 WANT_* 列表，不存在两套接线。

3.2 每帧运行时循环

EngineApp._tick(dt) → 累加 self.time → update(dt)（内核经 ctx.economy/rules/entity/render 推进游戏状态）→ render()（engine.Renderer 跑：天空 pass → MRT 几何 pass 不透明→半透明排序 → SSAO → Bloom → 合成曝光/ACES/gamma → 屏幕）→ HUD 叠层 / 截图 capture / 音频同步 / perf 采样 → 回到下一帧。

platform/app.py 的 DemoApp 与 engine/app.py 的 EngineApp 是同一骨架的两份：前者供独立演示仓、后者是引擎库内统一入口，均统一命令行（--smoke/--shot/--bench/--size/--flag）。

3.3 场景数据来源

场景 JSON（LLM 生成 / 手写）→ engine.scene_build.validate（纯 CPU 校验，无窗口可跑，挡住 LLM 幻觉参数）→ build_meshdata / build_material（生成器 builder → MeshData）→ Scene（Node TRS 场景图，脏标记 + 视锥剔除收集）→ 被 Renderer 消费。serialize.py 提供 JSON 热重载 watcher。

4. 关键技术决策与踩坑（精选，均真机复现）

主题决策 / 结论
环境贴图等距柱状 equirect（非立方体贴图，pyglet 无 CubeMap 类）
IBL 镜面逐 mip 级 GGX 重要性采样 + textureLod(roughness*maxLod)，非单张大模糊核
G-bufferMRT 两张（HDR 颜色 + 视空间法线/线性深度），非全延迟
debug_gl关掉 pyglet.options['debug_gl']（每 GL 调用 glGetError 往返占每帧 Python 耗时 ~44%）→ 基准 28.7→114.7 fps
P0 模型矩阵 uniform 去重 bugMesh.draw() 原按「本网格上次传了什么」去重，导致第 2 帧起多网格共用 program 级 uniform 互相覆盖，画面塌到最后一物。修复：去重键改为「该 program 当前装着的矩阵」（模块级 _MODEL_UNIFORM）；守卫 test_gl_multimesh_frame_stability（连续三帧逐字节一致）。
横向依赖清理unit_cube/unit_sphere 曾被 6 个内核横向 import（游戏 A 依赖游戏 B），迁至 engine.baked_mesh；「删定义」与「补 import」必须在同一次改动完成（否则 NameError 被 Cordis Loader 吞成「服务不就绪」）。
可逆副作用Cordis ctx.effect 绑定 fiber，dispose 时统一回滚；内核 GL 资源经 render.release + ctx.effect 注册，卸载即回收。
headless 验证render_core 不真开 GL 也完整执行记账/回滚语义；CI 用 PYGLET_HEADLESS=1 + EGL(llvmpipe) 跑无显示器用例。
DPI 坑统一 pyglet.options['dpi_scaling']='real'（否则 viewport 乘 scale 渲染放大裁切）。
