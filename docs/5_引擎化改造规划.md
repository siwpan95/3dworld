## 2. 定位：做成一个**什么样的** 3D 引擎

### 2.1 差异化定位（调研后的判断）

> **3dworld = 纯 Python 的"程序化优先 + 确定性 + 可 headless 验证"的 3D 场景/动画引擎。**

四根支柱（都是现状已经证明过的强项，不是许愿）：

1. **程序化优先 / 零素材**：几何、纹理、场景、配乐全部代码生成（`proctex`/`geometry`/`kkrieger_scene`/`KKOST`）；
2. **确定性**：`core/_rng.py` 的 LCG、`--seeds` 逐字复现、`record_all` 离线定帧录制；
3. **可 headless 验收**：`config_boot`（内核）+ `verify_demos`（31 个示例冒烟/抓帧）+ `run_all_tests`（138 项）——**引擎级**的质量门禁比同类项目厚；
4. **声明式插件宿主**：vendored Cordis + 9 棵 YAML 配置树 + 15 个 `Protocol` 契约（`core/contracts.py`），
   做到"改配置换玩法"，且**非 MIT 参考源只读思路不搬码**。

### 2.2 明确**不做**（避免范围失控）

| 不做 | 理由 |
|------|------|
| 多后端 RHI（Vulkan/D3D/Metal） | 现状是 pyglet + GL 3.3；`docs/pyglet3_迁移预研.md` 已评估。**只留薄抽象 + 能力探测 + CPU 回退** |
| 编辑器 GUI（场景刷/材质刷） | 已用"场景 JSON + 查看器 + 导演台 + 热重载"替代，性价比更高 |
| 网络/多人同步 | 无需求，且会把确定性优势拖进泥潭 |
| 引入重外部依赖（allin_engine / bloodmusic / zhuangtaiji / numpy 级） | 与"零外部依赖"纪律冲突；且这些库源在本机（G 盘）已离线，**无法复现** |

### 2.3 生态位（调研对照）

| 项目 | 定位 | 与我们的关系 |
|------|------|-------------|
| Panda3D | C++ 场景图 + Python 绑定，生产级 | 对标"能力天花板"，我们**不与它比性能** |
| Ursina | Panda3D 之上的纯 Python 高层封装 | 教训：高层 API 别用反射/动态属性查找（GC 抖动）；提供对象池 |
| moderngl | 低层 GL 绑定，手管状态，快 | 教训：我们**不**下沉到它那一层；保留 pyglet 生态 |
| Arcade | 2D + 自动实例化 | 参考其"示例即文档"的组织方式 |
| Infernux（2026 论文） | Python 原生引擎 + JIT + **帧图注入点** | 直接借鉴其**渲染拓扑注入点 + 资源总线**设计（§3.4） |

## 3. 目标架构

### 3.1 分层与依赖方向（铁律：只能向下，反向禁止）

```
games/ · examples/            ← 游戏与示例（原来 demos/）
   ↓
subsystems/                   ← 引擎高层子系统（原 core/*_core + services + 新转正）
   ↓
scene/ anim/ audio/ render/   ← 场景图 · 时间轴/蒙皮 · 音频 · 渲染管线
   ↓
platform/                     ← 窗口/输入/文件/DPI/字体（原 engine/app.py + demos/_harness.py 抽合）
   ↓
core/                         ← 纯内核：数学/时间/几何/序列化/契约/资源（无 GL）
```
* 现状已有的是 `app → renderer → postfx/mesh/scene → 纯数学层`，本条只是把它**补全到全域**并加门禁。

### 3.2 目标包结构（建议）

```
3dworld/                     # 仓库根（发行名可保留 3dworld）
├── pyproject.toml           # 单一事实来源（PEP 621）：元数据/依赖/extras/入口点
├── world3d/                 # ← 导入包名（见 §7-Q1；不能叫 3dworld）
│   ├── core/                # 无 GL：mathkit timeline frustum geometry serialize contracts rng resources
│   ├── platform/            # window input files dpi fonts hud
│   ├── render/              # rhi(薄) shaders material mesh targets postfx passes renderer
│   ├── scene/               # node scene build
│   ├── anim/                # timeline skin shot(演出)
│   ├── audio/               # track render ost sfx adaptive
│   ├── subsystems/          # render_core economy_core entity_core … （13 共同核）+ 新转正者
│   ├── host/                # tree.py（配置树宿主）contracts 校验
│   ├── cli/                 # config_boot / verify / record / build 的统一入口
│   └── _vendor/cordis/      # vendored（或继续顶层 vendor/）
├── games/                   # 8 个玩法内核（转正后）
├── examples/                # 原 demos/（32 个示例）
├── configs/                 # 原 experiments/cordis/*.yml（9 棵树）
├── tests/ + conformance/    # 单元 + 契约一致性门禁
├── docs/ assets/ scripts/
└── VERSION  CHANGELOG.md  LICENSE
```

### 3.3 公共 API 面与版本策略

* **公共面**：`world3d/__init__.py` 用 `__all__` 显式收口（现状 `engine/__init__.py` 已做类似事）；
  加 `py.typed`；**内部模块一律下划线或 `_internal/`**。
* **插件 ABI**：`core/contracts.py` 的 15 个 `Protocol` + `verify()` **就是引擎的扩展契约**，
  提升为正式承诺面，并进 CI（`conformance`，§6-P1 验收）。
* **双轨版本**：库 `SemVer`（`world3d.__version__`，破坏性变更才 +MAJOR）；
  发行版（Gitee release / exe / 成片）继续 `CalVer`。
* 弃用策略：先 `DeprecationWarning` 一版，再删；旧路径保留**兼容再导出层**（`logic/*.py` 已有此先例）。

### 3.4 渲染管线：轻量帧图（④ 的地基）

调研结论（Frostbite FrameGraph / UE5 RDG / Filament FrameGraph / Infernux 注入点）里的**落地优先级**是
"**先做资源跟踪与 Pass 裁剪，再谈内存别名与异步调度**"。落到我们（GL 3.3，无显式 barrier）：

| 层 | 现在 | 目标 |
|----|------|------|
| Pass 组织 | `Renderer.render` 里命令式 `if post.settings.ssao_enabled:` … | **声明式 Pass 链**：每个 Pass 声明 `reads/writes`（虚拟资源名） |
| Pass 裁剪 | 无（关掉效果也照样跑代码路径） | **反向可达性裁剪**：输出无人消费的 Pass 自动跳过（关 SSR 不必手写 `if`） |
| 资源生命周期 | 手管 `RenderTarget`/`MipTarget` | 由图推导 first/last use → 复用/别名（GL 下先做**尺寸+格式复用池**） |
| 扩展点 | 改 `renderer.py` | **注入点（injection point）+ 资源总线**：`before_post` / `after_post` 等命名槽位，④ 的体积雾/DoF/运动模糊各挂一个 Pass，**不动 renderer** |
| 能力降级 | 已有先例（GPU 剔除 → CPU 回退） | 统一为 `Capabilities` 探测表 + 每个 Pass 声明 `requires` |

## 5. 调研支撑（来源 → 要点 → 我们的决策）

| # | 来源 | 要点 | 落到本规划的决策 |
|---|------|------|-----------------|
| 1 | 游戏引擎核心设计原则（gamedev.net 转载整理） | 模块化/关注点分离/数据驱动/依赖最小化；分层 `game → high-level → low-level → core → OS`；ECS 用组合代替继承 | §3.1 分层与依赖铁律；§3.2 目录；**不整体改 ECS**（场景图保留，玩法层已有 `entity_core`） |
| 2 | 游戏引擎渲染系统架构（分层/RHI） | "逻辑层 → API 抽象层 → 平台层"；**接口稳定、实现替换**；过早耦合 API 等于以后重写 | §2.2 明确**不做多后端 RHI**，但 §3.4 保留薄抽象 + 能力探测 |
| 3 | Game Engine Architecture（Zenodo, 2026） | 资源加载/流式/引用计数/热重载；插件架构、接口化、服务定位器、事件系统；Job 系统与 GIL | §3.3 插件 ABI（契约即接口）；§2.2 不做网络；并发沿用"进程/子进程桥"（Cordis 已是进程外） |
| 4 | Frame Graph / Render Graph（Frostbite GDC2017、UE5 RDG、Filament、Traktor 文档、Vulkan 教程） | DAG：Pass 为节点、资源为边；反向可达性裁剪；资源生命周期 → 别名；屏障自动插入；**注入点 + 资源总线**；落地优先级"先跟踪/裁剪、后别名/异步" | §3.4 **轻量帧图**（GL 下重点是 Pass 裁剪 + 注入点）；④ 的体积雾/DoF/运动模糊各成 Pass |
| 5 | Infernux（arXiv, 2026，Python 原生引擎） | 渲染拓扑由 Python 子类声明的**注入点**；`before/after_post_process` 默认槽位；资源总线传纹理句柄 | §3.4 注入点命名与"效果自动拿到更新后的句柄" |
| 6 | Python 打包最佳实践（PEP 621 / pyproject / src 布局 / SemVer） | `pyproject.toml` 单一事实来源；`src/` 布局强制"测的是装出来的包"；库用 SemVer、应用用 CalVer；`__all__` 定义公共 API；`py.typed`；`[project.scripts]` 做 CLI；extras 管可选依赖 | §3.2/§3.3；§6-P1；**并纠正现状**：`VERSION` 是 CalVer（应用口径），库需另设 SemVer |
| 7 | Python 3D 生态位（Panda3D / Ursina / moderngl / Arcade 对比） | Ursina 的反射式高层 API 在大场景有 GC 抖动；moderngl 快但要手管状态；Panda3D 是 C++ 场景图 | §2.3 定位与教训；§2.2 不引重依赖 |

## 6. 阶段路线（每阶段独立验收 + 单独提交推送）

### P0 · 试点转正（本规划的"第一刀"，低风险高收益）

* **范围**：§4 的 A / B / C 三组（内核 + 服务壳 + 宿主/配置树）+ D 组的 `greedy_mesh`
  （它是"从 kernel 上提到 engine"这一模式的**样板热身项**，与已有 `core/render_core` 先例同型），
  合计 ~5300 行迁移。
* **拆批（每批单独提交 + 推送，各自跑门禁）**：
  * **P0-1** `greedy_mesh` → `engine/greedy_mesh.py`（最小热身，验证迁移手法）
  * **P0-2** 宿主与配置树：`tree_boot` → `host/tree.py`，9 棵 yml → `configs/`，`config_boot` → `cli/`
  * **P0-3** 8 个玩法内核 → `games/`（**最大的一批**，同步改 8 个 demo 的 import + yml + tests/docs）
  * **P0-4** 20 个手写服务壳 → 动态发现（保留一版兼容表）
* **手法**：`git mv` 保历史 + 更新 import/yml/tests/docs + **旧路径留兼容再导出层一版**。
* **验收**：`scripts/run_all_tests.py` 7/7 模块 138 项；`config_boot all` 全 OK；
  `verify_demos`（31 个）ALL_DEMOS_OK；`python -m world3d.cli.config_boot all` 与旧入口输出一致。

### P1 · 库化（可安装 + 公共 API 面）

* `pyproject.toml`（hatchling/setuptools，`[project]` + extras：`dev` / `pyglet1x` 兼容 / 未来 `ai`）；
  三份 `requirements*.txt` 收口（保留一份 lock 语义的 `requirements-lock.txt` 或删）；
  `world3d/__init__.py` 用 `__all__` 导出公共面 + `py.typed`；
  `[project.scripts]`：`world3d-demo` / `world3d-config` / `world3d-verify` / `world3d-record`；
  库 SemVer 起步 `0.1.0`（`0.x` 期间允许破坏）。
* **验收**：干净 venv 里 `pip install .` → `python -c "import world3d"`；`pip install -e .` 后 138 项测试全绿；
  `world3d-config all` 跑通；**不允许**再从仓库根 cwd 隐式 import（`src/` 布局留到 P2 一次性做）。

### P2 · 分层归位（还 §1.2 的 6 条债）

* 抽 `platform/`（窗口/输入/DPI/字体/HUD）；`demos/_harness.py` 变成 `platform.app` 的薄兼容层；
  把 `core/renderer.py`、`core/kkrieger_scene.py`、`core/nordic_scene.py` 清出到 `examples/` 侧或 `content/`；
  `demos/` → `examples/`（README/verify/record/发行版描述同步改）；
  **一次性**决定 `src/` 布局（建议此时做，`git mv` + `--follow`）。
* **验收**：依赖方向门禁（新增 `conformance/test_layering.py`：扫 import 生成依赖图并断言无反向边）；
  138 项 + 31 示例 + config_boot 全绿；录制 24 条成片抽查 3 条与旧版**逐帧一致**（保证重构不改画面）。

### P3 · 帧图管线（承接 ④）

* 先做**Pass 链 + 注入点 + 反向裁剪**（§3.4），④ 的体积雾 / DoF / 运动模糊 / CSM 各挂一个 Pass；
  再做资源复用池；异步/别名不做（GL 下收益低）。
* **验收**：关掉某效果时该 Pass **确实不执行**（用 `--bench` 的 draw_calls/pass 计数断言）；
  四个新效果可独立开关；`--bench` 帧率不因框架而回退（阈值写进验收）。

### P4 · 收尾（文档 / 门禁 / 脚手架）

* 文档站（MkDocs，`docs/` 现成 15 篇可复用）：Quickstart / 架构 / 公共 API / 扩展契约 / 迁移指南；
  `conformance/` 门禁（公共 API 快照对比、契约 `verify()`、依赖方向、示例全跑）；
  `world3d new <demo>` 模板脚手架；`CONTRIBUTING` + 弃用策略。
