## 四、待复核

1. ~~**CDLOD 许可**~~ —— **已结案**：`LICENSE` 原文为 MIT（Copyright (c) 2010 Filip Strugar）。
2. 帧图 v2 的 `peak_bytes` 是**上界口径**（按 format 位宽 × 尺寸 × 采样数估算），不是实测显存；断言只用于"相对变化"，不要当绝对预算用。
3. 跨帧池目前**只做数据结构与借还**，尚未接 GL 纹理分配；接线时需确认 `release_plan()` 在所有异常路径上都会被调用（否则槽位泄漏）。
4. **本轮（2026-10-20）§二 五项评估结论：跳过，不落地**。统一根因是它们超出本仓 engine 层「纯数学 / 无 GL / headless 可编译校验」的定位，逐项理由：
   - **Jolt 刚体 / Box2D 软约束**：落地需要真实的碰撞检测（broadphase / GJK-EPA / 接触流形）、约束 solver 与迭代收敛、刚体/形状数据结构与积分器——一整套物理运行时。本仓无物理后端，且与「纯数学、无 GL」层冲突；而本仓已落地的 `test_physics3d`（自研碰撞/扫掠/积分）已覆盖该定位内的部分，故 Jolt/Box2D 不搬。
   - **ozz-animation 动画采样/混合**：落地需要骨架层级、采样/混合/分层/加法/root motion 的动画管线，以及动画资源（clip/skeleton）加载——属运行时 + 资源层，非纯算法。本仓 `test_skin`（蒙皮骨骼）已是该定位内的自研实现，故 ozz 不搬。
   - **Filament 材质变体编译缓存**：落地需要 GLSL/MSL 着色器编译、变体键 → 产物映射与磁盘缓存，属渲染后端 + 着色器工具链层，直接依赖 GL/后端。本仓 framegraph / CSM 等只做"无 GL 也能编译/校验"的数据结构与算法，故 Filament 不搬（若将来真搬代码须补 `THIRD_PARTY_NOTICES` 与 Apache 专利条款声明）。
   - **glTF 扩展矩阵（KHR_materials_* / EXT_meshopt / KHR_texture_basisu）**：落地需要完整的 glTF loader 与扩展解析/烘焙管线，属资源加载层（且本仓已有 `test_source2` / `test_meshopt` 覆盖 meshopt 解码这一纯算法子集）。按规范实现扩展无需第三方 loader，但整套 glTF 解析超出当前定位，故本轮不落地。
   - 三项**已落地**的算法（二进制贪心、几何 clipmap、顶点 AO）之所以可行，正是因为它们落在「纯数学 + 数据结构的算法」档内，与 CDLOD 同一定位；上述五项则需越过该红线，故跳过、仅保留许可预登记。
