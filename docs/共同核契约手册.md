> 2026-10-19 建（能力复盘建议 3）。13 个共同核的**职责 / 方法表 / 不变量 / 消费者**。
> 与 `world3d/core/contracts.py` 的注册表、`world3d/host/tree.py` 的 `WANT_CORES`

> 核名 ↔ `WANT_CORES` **双向一致** —— 加了核忘了写手册会红。

## 逐核契约

### audio — 程序化音频

- **职责**：波形/音效/音轨的程序化合成与播放，零外部音频素材。
- **方法表**（`AudioCore`）：`tone` / `noise` / `create_track` / `render_wav` /
  `play_music` / `sfx` / `available`
- **不变量**：同参数两次合成逐字节相同（确定性）；`render_wav` 输出为标准
  WAV 容器（`test_cores` 钉住结构）。
- **消费者**：pulse（谱面程序化配乐）；kkrieger / nordic / liminall 的配乐在
  `logic/*_audio.py`（同家族，不经核挂载）。

### economy — 资源经济

- **职责**：资源存量 + 收支校验（塔防的「经济→兵力」循环、太空贸易的资金）。
- **方法表**（`EconomyCore`）：`balance` / `add` / `spend` / `harvest` /
  `enqueue` / `tick`
- **不变量**：`spend` 不透支（余额不足被拒且不改变状态）；收支序列可复现。
- **消费者**：td / godhand / fps / storm / void / pulse。

### entity — 实体注册表

- **职责**：通用实体（带 id 与组件字典）的注册/查询/更新/移除。
- **方法表**（`EntityCore`）：`spawn` / `get` / `query` / `update` / `remove` / `count`
- **不变量**：id 唯一且不复用；`query` 条件过滤不改变注册表。
- **消费者**：td / godhand / fps / puzzle / storm / void。

### inventory — 背包

- **职责**：槽位 + 堆叠 + 装备槽（P1-⑤ 玩法通用件）。
- **方法表**（`InventoryCore`）：`register` / `add` / `remove` / `has` / `count` /
  `equip` / `unequip` / `used` / `clear` / `total_value`
- **不变量**：堆叠不超上限；装备槽互斥（同槽位换装先卸后装）。
- **消费者**：暂无内核（就绪待用；`test_cores` 覆盖）。

### loot — 掉落

- **职责**：权重掉落表 + 保底 + 词缀，全部种子确定性。
- **方法表**（`LootCore`）：`table` / `affix_table` / `roll` / `drop_from` /
  `expected_value`
- **不变量**：同种子同表两次 roll 逐字相同；保底触发后计数归零。
- **消费者**：暂无内核（就绪待用；`test_cores` 覆盖）。

### particles — 粒子

- **职责**：粒子状态 + 数值步进（headless 安全，无 GL）。GPU 渲染集成在
  `engine/particles.py`（0.2.0 上提），两者经「状态→快照」衔接。
- **方法表**（`ParticlesCore`）：`emit` / `update` / `set_count` / `snapshot` / `draw`
- **不变量**：`update` 纯数值（不碰 GL）；`snapshot()` 渲染层只读。
- **消费者**：storm（击杀碎屑/命中火花/受击冲击）。

### pathing — 寻路与编队

- **职责**：网格 A* + 编队布局 + Flock 群体行为。
- **方法表**（`PathingCore`）：`find_path` / `formation` / `positions` /
  `velocities` / `step` / `set_predator`
- **不变量**：A* 路径连续（相邻点曼哈顿距离为 1）且不穿墙；同种子编队确定。
- **消费者**：storm（编队进场；pathing 核首个内核消费者）。

### render — GL 资源原语

- **职责**：着色器程序/网格/纹理等 GL 资源的创建、记账与**可逆回滚**
 （场景重建不泄漏 VBO）。
- **方法表**（`RenderCore`）：`program` / `render` / `resize` / `set_point_lights`
- **不变量**：资源创建全部入账；`rebuild` 后账实相符（`test_engine` 的
  多网格连续三帧逐字节一致用例即此契约的延伸）。
- **消费者**：全部 9 个内核（通用件）。

### rules — 波次与胜负状态机

- **职责**：波次/胜负状态机（塔防、神之手、FPS 三口径的统一抽象）。
- **方法表**（`RulesCore`）：`state` / `on_event` / `win` / `lose` / `reset`
- **不变量**：终态不可逆（won/lost 后 `on_event` 不改变状态）；`reset` 回到初态。
- **消费者**：全部 9 个内核（通用件）。

### sdf — 体素与距离场

- **职责**：体素读写 + 面剔除网格 + 光线步进程序取用；距离场与命中判定同源。
- **方法表**（`SdfVoxelCore`）：`voxel_get` / `voxel_set` / `world_mesh` /
  `block_at` / `raymarch_program`
- **不变量**：`world_mesh` 的剔除版与全量版几何同源（只差 cull 开关）；
  距离场查询确定。
- **消费者**：cores 树挂载；fps 的迷宫距离场底层（godhand 亦引用其体素件）。

### skills — 技能树

- **职责**：技能树 + 前置图 + 属性面板（P1-⑤ 玩法通用件）。
- **方法表**（`SkillsCore`）：`define` / `can_learn` / `learn` / `level` /
  `add_points` / `respec` / `effects` / `stat` / `has` / `is_neutral`
- **不变量**：前置未满足不可学；`respec` 全额返还且不丢已学记录。
- **消费者**：暂无内核（就绪待用；`test_cores` 覆盖）。

### terrain — 可编辑高度场

- **职责**：可编辑高度场（抬山 +/ 挖海 −）+ 网格重建，纯数值无 GL。
- **方法表**（`TerrainCore`）：`height_at` / `color_at` / `edit_height` /
  `regenerate` / `rebuild_mesh` / `ground_height`
- **不变量**：同 seed 同点同值（确定性）；`rebuild_mesh` 只产顶点数组。
- **消费者**：godhand（「抬山/挖海」实时改写地形）。
- **同族提醒**：`logic/terrain.py`（0.2.0 上提的 fBm 程序化地形）是**另一条线**——
  本核是「可编辑高度场服务」，那条是「程序化地形网格」，互不依赖。

### timeline — 时间轴

- **职责**：Sampler / Channel / Timeline / PlaybackController 四件套，
  关键帧插值与播放控制。
- **方法表**（`TimelineCore`）：`make_sampler` / `make_channel` / `make_timeline` /
  `make_playback`
- **不变量**：插值端点命中（t=键时刻取键值）；循环播放首尾无缝。
- **消费者**：引擎内部（`engine/timeline.py`、`presentation/timeline_ui.py`、
  各演出的编排层直用，不经内核挂载）。

## 与注册表的关系

- **权威源**：`world3d/core/contracts.py`（协议类 + `CORES` 注册表）与
  `world3d/host/tree.py`（`WANT_CORES`）—— 代码说了算。
- **本手册**：人类可读的镜像。方法表以协议类为准；若协议类改了方法签名而
  手册没跟上，`cores-doc-pairs` 只核对**核名清单**（方法签名的同步靠
  `test_cores` 的导入面 + 评审习惯）。
- **新增一个核的完整清单**：协议类 → `CORES` 注册 → `WANT_CORES`（若要挂载）→
  本手册总览表 + 逐节 → `configs/cordis.cores.yml` → 测试。`new_kernel.py`
  管前三步的骨架，后三步由门禁与评审兜底。
