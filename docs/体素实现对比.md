# 体素实现对比：`voxel_terrain.py` × `minecraft_style.py`

> 两个 demo 都做「方块世界」，但**定位不同**：`voxel_terrain` 是「面剔除」的
> **教学实验**（同一份数据、同一段代码，只切 `cull` 开关，把"省了多少"实时摆在
> 眼前）；`minecraft_style` 是「方块世界」的**产品级短片**（五幕 48s、昼夜、
> 建造动画、生物）。机制差异全部可以从定位差异推出来。2026-10-09 分析。

## 总览

| 维度 | `voxel_terrain.py`（465 行·自包含） | `minecraft_style.py`（493 行）+ `logic/blocks.py`（~830 行） |
|------|------|------|
| **定位** | 面剔除教学：双网格 A/B（H 切换）+ 实时剔除率 | 五幕动画短片：昼夜/建造/生物/云 |
| **世界表示** | **隐式高度图**：`heights[z*W+x] ∈ [1,14]`，`y<h` 即实心——**没有 3D 数组** | **显式 3D 字节数组**：`bytearray(72×26×72)`，15 种方块 ID + 空气 |
| **生成算法** | 白噪声 → 3×3 均值滤波 ×3 → 混回 28% 原始噪声 → 量化到 1~14 层 | 值噪声 fbm（4+2 八度）→ 地表高度 → 分层填充（石/土/草/沙/雪）→ 树/村庄/湖 |
| **剔除规则** | **单条**：邻居高度 > y 即实心（世界外=空气；y<0=地基） | **分类**：邻居非空气即挡——但水-水互不挡、半透明不挡、水下底面不画 |
| **顶点属性** | position + color（分层色×面亮度，**无 UV**） | position + color（亮度 + **emissive alpha**）+ **UV（图集）** |
| **外观系统** | 无贴图——纯顶点色 | **程序化 16×16 像素图集**（23 格贴图 + 生物/云 6 格）；哈希规则现算、NEAREST + 半像素内缩 |
| **着色器** | 9 行（直出顶点色） | ~45 行（图集采样 / cutout / 天光 uniform / 雾 / 水面 UV 滚动） |
| **光照** | 逐面亮度烘进顶点色（顶 1.0 / 侧 0.8 / 底 0.5 思路同源） | 同思路 + **全局天光 uniform**（昼夜零重建）+ 自发光走顶点 alpha（"日落点灯"零成本） |
| **绘制批次** | 单批 | **两批**：不透明 / 水（半透明单独混合） |
| **动态机制** | 换种子 = **重建世界**（按列分段渐进，~6ms/帧预算）；"全部面"网格懒建 ~150ms 对照 | 昼夜=改 uniform、下落方块/云=**实例化管线**（i_pos/i_anim）、生物=六盒体模型矩阵 + `mob_pose` 纯数学步态——**零网格重建** |
| **数据上传** | `array('f')` 一次性拼（全面网格约 40 万顶点级；Python list 会多占几十 MB） | `array('f')` 追加（pos/col/uv 三数组）；`mesh_world(y0,y1)` 支持分层渐进 |
| **实测锚点（单测）** | 暴露 9762 / 全部 70422 面 → **剔除 86.1%** | 图集 368×16 / 23 格；世界 20628 面（水 1188）→ **剔除 96%** |
| **代码组织** | demo 内自包含 | **逻辑/渲染分层**：`blocks.py` 不 import GL——纹理是像素字节、网格是 float 数组、步态是角度——全部可无窗口单测 |

## 深入：为什么这样切

### 1. 世界表示：隐式 vs 显式
- `voxel_terrain` 只需要「高度场」——隐式表示让**剔除退化成整数比较**
  （邻列高度 vs 当前 y），三行判断、无邻居坐标运算；
- `minecraft_style` 需要洞穴、树冠悬空、建筑、水面——**必须**完整 3D 体素；
  代价是剔除要按 15 种方块分类（水/半透明/水下底面各有规则）。

### 2. 外观：顶点色 vs 像素图集
- 教学场景里**颜色即外观**（分层色 + 顶亮侧暗已足够可辨），省掉 UV/图集/采样全链路；
- 方块世界的"灵魂"是 16×16 像素贴图：`tile_pixels(name)` 用哈希噪声 + 图案规则
  **现算 23 种贴图**（零外部素材），NEAREST 采样 + 半像素内缩（防渗色）+
  cutout（火把透明像素 `discard`）。

### 3. 动态：重建世界 vs 驱动参数（最本质的分歧）
- `voxel_terrain` 的"动态"= 换种子——**数据本身变**——重建成本是主角，
  于是有了按列分段 + 时间预算的渐进策略；
- `minecraft_style` 的"动态"= 昼夜/建造/生物——**不重建网格**：
  天光是 uniform 乘法、下落方块是实例属性、生物是每帧几个模型矩阵——
  **同一份网格，驱动整部 48s 短片**。

### 4. 共同的工程习惯（两条路线的"公约数"）
- 都用 `array('f')` 而非 Python list（几十万顶点级的内存/速度考量）；
- 都走**确定性**路线（哈希噪声 + 固定 seed——截图可复现、单测可断言）；
- 都把「亮度分级」烘进顶点色（同一套 MC 观感方法论）。

## 一句话总结

**`voxel_terrain` 把「剔除」做成显微镜**——同数据、同代码、cull 开关、
A/B 数字就在 HUD 上；**`minecraft_style` 把「剔除」藏进生产线**——分类规则、
两批网格、参数化动态。前者解释原理，后者兑现规模；两条路线共享同一个核心信仰：
**只有暴露在外的面，才值得画。**
