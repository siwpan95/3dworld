## 1. 方向判断：为什么"3D 动画制作"适合本项目

当前 demo 已具备三维世界的全部要素（透视投影、Batch 几何、轨道相机、主循环），
缺的是**时间维度**。补上时间轴与关键帧插值，"静态世界"即升级为"动画制作工具"：

- 起点低：关键帧动画（TRS 通道 + 插值）不需要骨骼蒙皮即可产出效果；
- 与现有代码兼容：相机环绕本质就是一个"时间驱动的动画通道"；
- 生态契合：pyglet 2.x 原生支持 glTF 2.0 场景加载与模型实例化，动画数据模型可直接对齐 glTF 规范，未来导入导出无缝。

## 2. 分层架构（借鉴文章的三层思想，映射到本项目）

| 层 | 职责 | 本项目对应模块（规划） |
|----|------|------------------------|
| **核心层 core** | 底层能力：窗口/渲染/输入/资源 | `core/camera.py`（轨道相机）、`core/renderer.py`（窗口+投影+Batch）、`core/resources.py`（glTF/OBJ/材质加载） |
| **逻辑层 logic** | 场景与动画：与"怎么画"无关 | `logic/scene.py`（节点树）、`logic/timeline.py`（时间轴）、`logic/keyframes.py`（关键帧+插值）、`logic/events.py`（事件总线） |
| **表现层 presentation** | 用户所见：视口/面板/时间轴 UI | `presentation/viewport.py`、`presentation/timeline_ui.py`、`presentation/inspector.py` |

依赖方向：presentation → logic → core，**反向禁止**。逻辑层不 import pyglet.gl，
只产出纯数据（每帧各节点的 TRS），由核心层消费——这保证动画系统可脱离窗口单测。

## 3. 动画系统设计（对齐 glTF 2.0 数据模型）

### 3.1 数据模型

```
Timeline
 ├─ duration: float                     总时长（秒）
 ├─ channels: list[Channel]             通道列表
 └─ Channel
     ├─ target: NodePath                作用节点 + 属性（translation/rotation/scale）
     └─ Sampler
         ├─ input:  [t0, t1, ...]       关键帧时间戳
         ├─ output: [v0, v1, ...]       关键帧值（平移Vec3/旋转四元数/缩放Vec3）
         └─ interpolation: LINEAR | STEP | CUBICSPLINE
```

### 3.2 插值规则（按 glTF 规范）

- 平移/缩放：LINEAR 逐分量 lerp；
- **旋转必须用四元数 slerp**（欧拉角插值会产生非自然旋转）；
- STEP：阶梯保持；CUBICSPLINE：二期再上，先保 LINEAR。

### 3.3 求值循环

`update(dt)` → `timeline.advance(dt)` → 逐通道采样 → 写入节点 TRS →
`events.emit('frame', t)` → 表现层刷新。逻辑更新可降频（30Hz 采样 + 渲染插值），
遵循文章的"逻辑更新优化"原则。

### 3.4 事件系统

直接复用 pyglet 的 `EventDispatcher`（发布/订阅，天然满足松耦合要求），
自定义事件：`on_frame(t)`、`on_timeline_end`、`on_channel_changed`。不自造轮子。

## 4. 技术选型结论：留在 pyglet，不换引擎

| 库 | 3D 能力 | 控制力 | 结论 |
|----|---------|--------|------|
| **pyglet 2.x（现用）** | glTF/OBJ 加载、场景图、模型实例、Batch | 高（直接 GL） | **继续使用**：已有代码资产 + 动画编辑器需要渲染控制力 |
| Ursina | 高级封装（Entity 一行出方块） | 低 | 若目标是"快速做 3D 游戏"才换；做**工具**不合适 |
| Panda3D | 完整引擎（场景图/物理） | 中 | 重依赖、引入成本高，动画工具用不到物理 |
| moderngl | 裸 OpenGL | 最高 | 需自建一切，与本项目进度不匹配 |

pyglet 现成可用能力（实测文档确认）：
`pyglet.model.load('xx.glb')` → `scene.create_models(batch)` →
`model.create_instance(translation=Vec3(...))` → 每帧改 `instance.matrix`。
即"导入模型 + 实例级动画"两步就已打通，无需求人。

## 5. 分期路线图（每期可独立验收、独立提交）

- **M1 分层重构（无行为变化）**：✅ 已落地——demo 拆进 core/logic/presentation，
  EventBus 接线 on_frame/on_view_changed；逻辑层 6 项无窗口单测通过
  （相机位姿/钳制/推进/视图矩阵性质 ×2/事件派发），logic 包无 pyglet.gl 真实导入；
  旧入口 `pyglet_3d_demo.py` 保留为兼容 shim，新入口 `main.py`。
- **M2 动画系统最小版**：✅ 已落地——`logic/animation.py` 实现 glTF 对齐的
  Sampler（LINEAR/STEP + 下/上界钳制）/Channel/Timeline（循环播头 + 回绕事件）；
  四元数 slerp + 自研 `quat_to_mat4`（实测 pyglet 的 `Quaternion.to_mat4`
  输出为标准旋转矩阵的转置，已弃用并在代码注释中留档）；立方体改用带
  `model` uniform 的自定义着色器逐帧驱动，地面静态不变；相机自转已由
  时间轴编排取代；10 项逻辑单测全绿。
- **M3 播放控制 + 时间轴 UI**：✅ 已落地——`logic/playback.py` 播放控制器
  （播放/暂停/循环/倍速/seek，非循环播完自动停在末姿态）；`presentation/timeline_ui.py`
  底部面板（播放/暂停按钮、LOOP 开关、进度条 + 可拖动播头、时间读数，
  屏幕空间正交投影绘制，命中面板时拦截相机拖动）；快捷键 Space=播放/暂停、
  L=循环；14 项逻辑单测全绿。
- **M4 外部模型导入**：✅ 已落地（OBJ 路线）——实测发现 **pyglet 2.1.16 发行包
  仅内置 OBJ 解码器**（glTF 解码器在开发分支，未随版发布，DeepWiki 文档超前）；
  `core/resources.py.load_model()` 已按 pyglet.model.load 统一封装，
  待 pyglet 升级带 glTF 后 .glb 即插即用、调用方零改动。
  测试资产 `assets/gem.obj`（正八面体）由 `scripts/make_gem_obj.py`
  程序化生成（自产资产，MIT，无第三方来源）；gem 参与时间轴
  （浮动 + 自旋），`Model.matrix` 经 group 传播到 GPU。
  验收 = 场景中出现宝石模型按时间轴运动；CPU 端解码测试通过。
- **M5 骨骼动画（spike + 兜底）**：✅ 已落地——spike 结论（实测）：
  pyglet 2.1.16 无 glTF 解码器，蒙皮管线（skin/JOINTS/WEIGHTS/关节矩阵）
  不可行；按预定兜底实现**节点级层级动画** `logic/skeleton.py`
  （BoneNode/Skeleton：局部 TRS → world = parent.world @ local，
  父变换继承子节点），两段机械臂（seg1/seg2 枢轴在关节的盒体段）
  由时间轴 Z 轴摆动通道驱动，演示骨骼式联动。
  真实蒙皮演进前提：pyglet 升级带 glTF+skin（零成本接入现资源封装），
  或自研 glTF 解码器 + 蒙皮着色器（独立立项评估）。
  验收 = 20 项逻辑单测全绿（父子变换传播数学已锁死）。

## 6. 风险与对策

- pyglet glTF 蒙皮支持不明 → M5 前先做技术验证 spike，不通走节点级动画兜底；
- Python 性能（万级关键帧采样）→ 关键帧预排序 + 二分查找 + 降频采样，量级可控；
- 范围蔓延（做成游戏引擎）→ 本项目定位**动画工具**，物理/网络/音频明确不做。
