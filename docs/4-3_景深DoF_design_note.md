> 轨道：**④ 引擎渲染扩展**。前三项：④-1 CSM ✅ · ④-2 体积雾/光轴 ✅ · ④-3 景深（本批）。
> 剩余 ④-4 运动模糊。
> 相关：`engine/dof.py` · `examples/dof_focus.py` · `tests/test_dof.py`（12 项）·
> CHANGELOG「④-3」段（逐条改动与五个坑）。

## 1. 问题与判据

景深**不是**「把背景高斯模糊一下」。真实相机是**每一点按弥散圆（CoC）大小摊成一个圆盘**：

```
CoC = A·f·(z − z_f) / ( z·(z_f − f) )      A = 光圈直径 = f/N
```

于是"前景糊得快、背景糊得慢"这种不对称是**算出来的**。整条链最舒服的地方是：
**它全是 19 世纪的光学公式**，所以可以用摄影常识当判据，而且容差能收到 1e-9。

**本批的验收判据（可测）**：

| # | 判据 | 实测 |
|---|------|------|
| 1 | 超焦距恒等式：`focus = H` ⇒ `near` **恰为** `H/2`、`far` = ∞ | 差值 **0** |
| 2 | 景深端点恒等式：`near` / `far` 处的 CoC **恰好等于**容限 `c` | 偏差 **< 1e-14**（5 个对焦距离） |
| 3 | CoC 渐近线：`z→∞` 趋于 `A·f/(z_f−f)`，且偏差**严格遵从 `z_f/z`** 的 1/z 律 | 相对差 ≈ 3e-9 @ z=1e12 |
| 4 | 散景盘**面积均匀**：平均半径 = 2/3（均匀取极角会得 1/2） | 64 点 **0.6668** |
| 5 | 画面上的摄影事实：近侧 CoC 涨得快、远侧**饱和** | 1m **−85.6px** / 200m **+11.7px** |

> 判据 1+2 是这一批的支点：两条**互相独立**地钉住 CoC 公式与 near/far 公式，
> 任一边写错都会炸 —— 本轮就是靠它们发现"分母漏了 `2f`"。
> 判据 3 的第二半（**断言偏差遵从 1/z 律**）比写死阈值更有力：它排除了"凑巧接近渐近值"。

## 2. 关键设计决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | 光学链（CoC / 超焦距 / 景深范围）**全部放纯函数** | 这些才是会写错的部分，而它们**不需要 GL 就能断言**；demo 只剩"把距离图与颜色传下去" |
| 2 | CoC **带符号**（前负后正） | 前景与背景的处理方式根本不同（近场要 clamp、还要防止前景糊到背景上），符号是最省的载体 |
| 3 | 散景盘**烘进着色器常量**，不用随机数 | 静止画面不该"沙沙响"（随机抖动会），剧照/录屏要可复现。代价是换叶片数要重编译 —— 一次按键而已 |
| 4 | 采样盘**面积均匀**（`r = √((i+0.5)/n)`） | 均匀取极角会让盘心堆点 ⇒ 虚化亮斑**中心偏亮**、看起来像脏点。测试断言平均半径 = 2/3（不是 1/2） |
| 5 | 支持**正多边形**叶片（3/5/6/8） | 六边形散景是廉价镜头最易辨认的特征，也是最直观的"这套实现是真的在算"的证据 |
| 6 | 前景剔除按"**采样点自己的圆盘能否够到当前像素**" | 单纯 gather 会把前景颜色抹到背景上（前景 CoC 远大于背景）⇒ 物体边缘一圈"晕"。这条**只在有强前景虚化时才看得出来** |
| 7 | `u_dof_max_coc` 强制上限 | `CoC ∝ 1/z`，贴近相机时爆掉 ⇒ 采样半径失控、帧率雪崩 |

## 3. 本批踩到的五个坑（四个是**判据**错，不是实现错）

| # | 症状 | 根因 |
|---|------|------|
| 22 | 测试把 `z=2` 判成"背景" | 我随手写 `focus=10mm + focal=50mm` —— **合焦面在镜头内部**，物理上不存在。公式照样算出数、符号却是反的。⇒ 内核补显式守卫 `focus <= focal → ValueError`。**"能算出数值"不等于"配置合法"** |
| 23 | `focus=H` 时 `near` 比 `H/2` 差 0.08% | `dof_limits` 分母漏了 `2f`（标准式 `H + s − 2f`）。改成标准式后两边**精确**成立，容差从"差不多"收紧到 1e-9 |
| 24 | 3 叶散景被判"超出内切圆" | **测试**算多边形法线时多加 `π/blades` ⇒ 两套多边形差半个扇区 ⇒ **测试把对的实现判成错** |
| 25 | 一条没带消息的断言失败 | `coc_pixels` **保留符号**，测试却拿带符号值比正数。现在断言显式 `abs()`，并额外断言"符号不能被悄悄丢掉" |
| 26 | 渐近线相对差 3e-6 "超阈值" | 那不是 bug，是真实的 1/z 收敛律。z 提到 1e12 + 断言"偏差遵从 `z_f/z`" |

> **教训（值得写进下一批的检查表）**：判据里的**每一个数字都要有物理/数学出处**
> —— 单位自洽、方向、符号、量级。否则"测试红了"与"实现错了"会被混为一谈；
> 本批出现两次"测试把对的实现判错"，都是因为判据里的数字是我"顺手"写的。
> 另外：**方向**也踩了一次（`N` 变大 ⇒ 近界是**变小**而不是前移），
> 现在断言旁边都写了"这个方向为什么对"。

## 5. 已知不足 / 下一步

1. **没做"两层分离"**（近景层 / 远景层分开 gather）：单层 gather 在"前景物体边缘"仍会有
   轻微的颜色渗透，双层分别 gather 再合成是工业做法；
2. **没做景深 + 体积雾的正确排序**：物理上雾应当**被虚化**（雾在焦外也要糊）。
   当前两者独立，若要同时开，顺序应是"先雾后景深"；
3. **没做自动对焦**（对屏幕中心/主体的距离取平均）；
4. **没进录制清单**：本批只出剧照。`--flag rack`（自动扫焦）其实很适合出成片，
   要出就加一条 `record_all.py` 条目（与 `brickward_60s` 同样的**攒批**口径）；
5. **④-4 运动模糊**仍未做 —— 它只需要相机重投影，不需要速度缓冲，是四项里最便宜的一个。
