# ④-1 级联阴影（CSM）设计说明

> 轨道：**④ 引擎渲染扩展**（承接 ③ 可视化导演台）。本批实现四项里的 **CSM**。
> 其余三项（体积雾 / 景深 / 运动模糊）留待后续。
>
> 相关：`engine/csm.py`（实现）· `examples/csm_shadow.py`（可玩 demo）·
> `tests/test_csm.py`（20 项）· CHANGELOG「④-1」段（逐条改动）。

## 1. 问题与判据

单张阴影图的精度是**固定**的：纹素在世界里的尺寸 = `2·半径 / 分辨率`。
半径 200 + 分辨率 2048 ⇒ 每纹素约 **0.2 世界单位** —— 近处物体影子边缘糊成锯齿；
把半径压到 20 保近处，远处就整片没阴影。

**本批的验收判据（可测，不靠"看起来对"）**：

1. 各级半径**逐级变大**、且"最细那级 / 最粗那级"的纹素比 < 0.5（本 demo 实测 **0.040**：
   最细 0.022、最粗 0.548 世界单位）；
2. 每一级的 8 个视锥角点，经该级光空间矩阵投影后**全部落在 [0,1]³ 内**，
   且**至少有一个角点贴到边界**（拟合是紧的，不是"随便套个大盒子"）；
3. 纹素吸附后世界原点**正好**落在纹素栅格上（残差 0）、位移 **< 1 纹素**，且**幂等**；
4. 生成的 GLSL 在**本机驱动上真编译一次**并真的上传 uniform（字符串层面看不出驱动是否接受）。

## 2. 关键设计决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | **纯函数式**：把分割 / 角点 / 光盒 / 吸附 / 选级全放进 `engine/csm.py`，不碰 GL | 这些才是会写错的部分，而它们**不需要 GL 就能断言**。demo 只剩"把矩阵和纹理传下去" |
| 2 | 光盒取 **正方盒**（`half = max(half_x, half_y) + pad`） | 长方盒会让纹素在 x/y 上尺寸不等，PCF 的采样半径就没法用一个标量表达 |
| 3 | 深度向两侧各撑 `z_extra`（默认 = 半宽） | 否则**处在光与视锥之间的柱子不投影** ⇒ 影子在远处"凭空断掉"，而且很难联想到是深度范围不够 |
| 4 | **必须做纹素吸附**（`texel_snap`） | 相机一动，光盒中心跟着漂 ⇒ 同一纹素采到的世界位置变 ⇒ 阴影边缘**闪烁/爬行**。这条**在静止截图里完全看不出来** |
| 5 | 选级用 **if/else 展开链**，不用 `u_csm_tex[i]` | GL 3.3 不允许用非常量下标索引 `sampler2D` 数组（GL 4.0 才放开动态 uniform 索引）。写成下标在多数驱动上**能编译、行为未定义**，是最难查的一类问题 |
| 6 | 每级一个**独立 `mat4` uniform**，不用 `mat4[N]` | 实测：pyglet 2.1.16 对 `uniform mat4 u_vp[4]` 的 `_c_array` 只按 **4** 个 float 分配（把 GL 报的"数组长度 4"当成"分量数"），`prog['u_x'] = [64 个 float]` 直接 `AssertionError`。独立 uniform 还正好和"展开链"一致 |
| 7 | `MAX_CASCADES = 4` 是**硬上限** | 着色器按上限展开编译，运行期只能在 `1..4` 之间切"用几级"（多余的级用同一套矩阵占位）。再往上"每级分到的分辨率"下降得比"半径缩小"快，收益为负 |

## 3. 本批踩到的四个坑（都写进了代码注释与 CHANGELOG）

| # | 症状 | 根因 |
|---|------|------|
| 14 | 改机位**完全没反应**，地面整片消失 | 从未设 `window.view` —— 平台层只在 resize 时设 `projection`，`view` 一直是**单位矩阵**；而地面正好在相机高度上被看成零厚度片 |
| 15 | 完全没有阴影，其余一切正常 | `glActiveTexture(GL_TEXTURE0+i); tex.bind()` —— pyglet 的 `Texture.bind()` **默认绑到 0 号单元**，N 张阴影图全挤在 0 号上。正解 `tex.bind(i)` |
| 16 | `mat4[]` uniform 上传直接 AssertionError | 见决策 6 |
| 17 | 深度图小窗一片黑，以为 render-to-texture 没跑 | 小窗显示的是**第 0 级**，而相机离场景 195m ⇒ 0~60m 本就是空空间，那张图**本来就该全远（全黑）**。换成中间那一级即可 |

> 另有两条 GLSL 硬约束，也写进了代码注释：
> **`uniform block` 必须在每个用到它的阶段各声明一遍**（只在顶点着色器声明、片段里用会
> `ERROR: 'window' : undeclared identifier`）；
> **PCF 核强制奇数**（`samples=2 → 3`），且循环边界必须是常量。

## 4. 与既有件的关系

| 件 | 关系 |
|----|------|
| `engine/soft_shadow.py`（PCSS） | **正交关系**：PCSS 管"一级之内怎么把边缘做软"，CSM 管"精度怎么分配到不同视距"。两者可叠加（本批没叠：先在 CSM 里用固定半径 PCF 把机制跑通） |
| `examples/shadow_map.py` | 单张阴影图的**基线**：CSM 的 demo 复用了它的两趟渲染写法（R32F + 手写 `glClear` 掩码），但把光盒换成了按级拟合 |
| `engine/camera.py` | `Camera.projection(aspect)` 与 `view_matrix()` 原样复用；**csm 用 mathkit 的列主序元组**，与相机的 pyglet `Mat4` 之间显式转一次（`mat4_from_Mat4`） |

## 5. 已知不足 / 下一步

1. **没做级间混合**（cascade blend）：级边界上仍是一条硬线。做法是最后一级往内留一段
   过渡带、按距离在两级之间 lerp —— 留待后续；
2. **没做光源空间裁剪**（light-space culling）：现在每级都把**整个场景**画进深度图；
   场景一大就是 N 倍 draw call。按光盒做视锥剔除即可，但那是 ④ 的另一件事；
3. **没叠 PCSS**：把 `soft_shadow.pcss_glsl()` 的动态半径与 CSM 的选级接起来是自然的下一步；
4. **没进录制清单**：本批只出剧照（`docs/csm_01/02.png`，已随 demo 迁往 3dworld-demos）。要出成片的话，
   加一条 `record_all.py` 条目即可（与 `brickward_60s` 同样的攒批口径）。
