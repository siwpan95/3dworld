# experiments/fixed_timestep —— 固定步长试点（P2 剩余项）

> 目标：验证「渲染帧率与物理更新解耦」对 3dworld 的价值（帧率无关 + 卡帧稳健），
> 交付可复用的调度器。依据：《docs/生态库引入评估.md》（allin `FixedTimestepLoop`
> 思路）；实现见 `engine/fixedstep.py`。2026-10-09。

## 方法

同一物理场景分别用两种驱动方式跑：
- **变步长**（现状）：`physics.step(dt, substeps=2)`，dt 随渲染帧抖动；
- **固定步长**（固定 1/60 + 单帧钳制 0.25）：`FixedStepper` 驱动。

## 实测数据（2026-10-09）

### A. 帧率无关性（自由落体+漂移：对比「落地事件」）

```
变步长  : 30fps 落地 t=0.7333s x=2.2000 | 144fps t=0.7222s x=2.1667
          Δt=0.0111s Δx=0.0333 m        ← 与帧率相关
固定步长: 30fps 落地 t=0.7167s x=2.1500 | 144fps t=0.7167s x=2.1500
          Δt=0.0000s Δx=0.0000 m        ← 逐位一致 ✓
```

### B. 卡帧稳健性（10 帧后插 0.5s 卡顿 + 薄墙 0.1m）

```
变步长  : 终点 x=  11.000  → 穿墙!     （0.5s 单步位移 3m 跨越薄墙）
固定步长: 终点 x=   2.750  → 拦住      （钳制 1 次生效，固定步数 55）
```

## 结论

1. **帧率无关**：固定步长下 30fps 与 144fps 物理结果**逐位一致**；变步长存在
   帧率相关偏差（本例 0.033m，高速场景会放大）；
2. **卡帧稳健**：单帧钳制直接消灭「卡帧 → 高速穿透」这一类事故（B 实证）；
3. **代价与边界**：固定步长下「末段不足一步」会残留到下一帧（`alpha` 供渲染
   插值；本引擎当前直出，差异在半帧内）——属离散化的正常行为。

## 接入建议（不急于改主代码）

- 现状风险：`substeps=2` 在卡帧下仍有穿透（B 证实），高速小物体尤甚；
- 建议在**交互化阶段**统一接入：把角色/交互物理改由 `FixedStepper` 驱动
  （1 行包装：`stepper.advance(real_dt)` 替代 `physics.step(dt, 2)`），
  届时手感对帧率稳定性更敏感，也便于回归对照。
